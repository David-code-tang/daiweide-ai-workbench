# 公众号文章骨架库

这批好文章大多从一个具体任务、反常现象或人物选择切入，再用实测、采访和过程细节推进，让读者看见判断是怎么得出的。它们的价值不在于把功能讲全，而在于解释“这跟我有什么关系、实际怎么用、什么时候不适用”；但高分文章也有证据缺口，借鉴结构时，要保留结论的适用范围。

## 1. 真实任务实测型：让 AI 做完一件事

- **适合什么选题**：新模型、新 Agent、新功能体验，回答“它现在能替我干什么”。

- **结构**：

  1. 用一个具体需求开场，交代谁遇到了什么麻烦，需要真实场景和原来的处理方式。
  2. 说明任务要求与完成标准，提供输入材料、使用版本和读者能理解的验收条件。
  3. 按关键节点展示执行过程，保留提示词、操作截图、人工介入和返工记录。
  4. 展示最终交付，并逐项检查是否满足要求，需要成品和核验结果。
  5. 总结适用场景与限制，依据本次成功和失败，说明哪些任务可以交给它、哪些还要自己盯。

- **关键**：第四步。漂亮截图只能证明“生成了”，检查成品才能证明“完成了”；还要交代作者替 AI 补了多少工作。

- **例子**：
  - 向阳乔木推荐看《三个月，豆包大模型进化了多少？7个案例自己判断》
  - 数字生命卡兹克《在折腾9个月后，手机Agent的王者，豆包手机助手它回来了。》
  - 葬AI《先进个人先搞豆包工作》

## 2. 痛点解决教程型：带读者拿到一个结果

- **适合什么选题**：可复用的 AI 工作流、Skill、自动化方法，例如整理资料、制作视频、修改图片。

- **结构**：

  1. 展示使用前后的差别，用原始材料和成品说明这套方法解决什么问题。
  2. 交代使用条件，列清需要的工具、账号、素材，以及读者必须先会的操作。
  3. 按最短可行路径拆解步骤，每步提供必要输入、操作方法和预期结果。
  4. 解释最容易卡住的地方，用真实报错、失败输出或纠错记录给出处理办法。
  5. 给出验收方法和复用入口，附提示词、模板或安装方式，并说明什么时候需要人工接手。

- **关键**：第三步。读者能否照着做出来，取决于输入是否完整、步骤是否连续、结果是否可辨认。

- **例子**：
  - 歸藏的AI工具箱《Grok Bot 玩法 01：生成 AI 早报视频的提示词》
  - 赛博禅心《Claude Mod 实测：让雨姐与你一同 Coding》
  - 歸藏的AI工具箱《Seedream 5.0 Pro 测评：图像编辑门槛爆降》

## 3. 对照选型型：帮读者做一个选择

- **适合什么选题**：模型对比、工具横测、免费与付费选择，回答“我的场景该用哪一个”。

- **结构**：

  1. 从选择困难切入，明确目标读者、候选工具和这次要解决的决策问题。
  2. 先定义比较维度，根据实际用途确定准确性、完成度、操作负担、耗时或费用等标准。
  3. 用相同材料执行相同任务，记录版本、条件、输出和人工修改情况。
  4. 解释差异发生在哪里，挑出关键成功与失败样本，说明它们对日常使用的影响。
  5. 按人群和任务给出选择建议，结合预算、频率和容错要求，说明各自适合谁。

- **关键**：第二、三步。标准必须服务于读者的任务；测试条件不一致时，要明确说明，避免把条件差异写成能力差异。

- **例子**：
  - 卡尔的AI沃茨《八款AI语音输入法大横测！我找到了Vibe Coding的最佳搭配》
  - 歸藏的AI工具箱《跟 Opus 4.8 打的有来有回？！Kimi K3 首测》
  - 葬AI《大模型拿大结果指南》

## 4. 人物选择访谈型：借一个人的经历讲清问题

- **适合什么选题**：普通人怎样用 AI 改变工作、创作者怎样调整流程、从业者如何面对职业变化。

- **结构**：

  1. 用人物最有张力的选择开场，需要一句原话、一个现场或一次出人意料的决定。
  2. 补足选择发生前的处境，交代人物目标、资源和约束，避免只展示成功后的状态。
  3. 追问关键行动与转折，用具体项目、操作变化和失败经历还原“他到底做了什么”。
  4. 追问代价和保留意见，需要被放弃的方案、仍靠人工完成的环节或尚未解决的矛盾。
  5. 回到读者可以借鉴的判断，区分人物的个人条件与他人能够复用的方法。

- **关键**：第三步。采访要从“你怎么看 AI”追到“上一次你怎么做、为什么改、结果怎样”。

- **例子**：
  - 数字生命卡兹克《汉化组，可能是世界上最不怕AI冲击的一群人。》
  - 数字生命卡兹克《那个拍出神作《牌子》的AI导演，带着他的巅峰之作回来了。》
  - 赛博禅心《买了这么多录音笔，我还是被元宝惊艳到了》

## 5. 反常现象拆解型：解释为什么会这样

- **适合什么选题**：AI 明明提效，人却更忙；同一个模型，换家公司就不好用；功能更强，用户却不愿使用。

- **结构**：

  1. 摆出一个违背直觉的现象，用具体案例或数据说明它确实存在。
  2. 补充不同角色的体验，需要使用者、执行者或管理者的材料，呈现现象内部的差异。
  3. 拆出两到三个作用机制，用流程、权限、成本、激励或使用习惯解释结果怎样发生。
  4. 检查其他可能解释，寻找反例和不同条件下的案例，限定判断范围。
  5. 落到读者的实际选择，根据已说明的机制，给出可执行的调整办法。

- **关键**：第三步。必须把“原因”连到具体行为和结果，不能用“认知不足”“组织问题”等大词代替解释。

- **例子**：
  - 人人都是产品经理《AI让人人都能做产品之后，真正稀缺的是什么？》
  - 晚点LatePost《汽车企业用 AI，为什么从飞书开始？》
  - 数字生命卡兹克《那些被管理层请进公司，却不被一线员工接受的FDE们。》

## 6. 观点推导型：从一次体验长出一个判断

- **适合什么选题**：纠正常见的 AI 使用观念，讨论效率、成本、可靠性，以及哪些能力仍值得人投入。

- **结构**：

  1. 从一次具体经历或新变化切入，提供促使作者重新思考的事实。
  2. 准确复述一个常见判断，用真实说法或典型行为交代大家为什么相信它。
  3. 展示这个判断解释不了的情况，用案例或实测指出它遗漏了什么。
  4. 提出更有解释力的判断，定义关键概念，并用不同案例检查它能否成立。
  5. 推出实际行动与适用边界，说明读者因此应该改变什么，以及什么情况下仍需保留旧做法。

- **关键**：第四步。新观点要能帮助读者重新判断具体问题；只有一句响亮口号，撑不起一篇文章。

- **例子**：
  - 赛博禅心《从 Token-Maxxing，到 Token-Minimizing》
  - 葬AI《AI Dating都是衡水中学》
  - 人人都是产品经理《企业级Agent的关键，不是自治，而是可控的结果生意》

## 7. 亲历改造复盘型：讲清一次改变怎样发生

- **适合什么选题**：用 AI 改造个人工作流、团队协作或长期项目，重点回答“从原来那套走到现在，经历了什么”。

- **结构**：

  1. 展示改造前最具体的堵点，需要原流程、重复劳动或协作失误的记录。
  2. 解释第一步为什么这样选，交代目标、资源限制和被暂时搁置的问题。
  3. 按关键迭代展开过程，用实际产物、使用反馈和失败记录说明每次调整的原因。
  4. 对照改造前后检查变化，需要时间投入、交付质量、使用情况或维护负担等证据。
  5. 提炼可以复用的经验，并交代观察时长、适用条件和尚未得到验证的部分。

- **关键**：第三、四步。复盘的价值在于展示如何根据反馈改变做法，并区分“搭出来了”“有人用了”和“持续有效”。

- **例子**：
  - 数字生命卡兹克《我花了5天时间，对公司进行了一场AI化改造。》
  - 数字生命卡兹克《开源百万月活级产品AIHOT，愿每个行业也都有自己的「AIHOT」。》
  - 歸藏的AI工具箱《开源 DeepSeek Harness 开箱即用客户端，还有几个易用插件》

## 好文章和水文的区别

1. **开头有一个能讲清的问题。** 检查前两三段：能否指出谁在什么场景遇到了什么事，以及为什么值得继续读？“AI 发展日新月异”没有提供这些信息。

2. **核心判断有对应材料。** 把“更强”“省时”“值得买”“改变行业”等判断圈出来，逐一检查旁边有没有实测、原话、数据或可追溯的案例。

3. **过程里有影响结果的细节。** 读者能否知道输入了什么、改过哪里、谁补了哪一步、最后交付什么？只有成品展示，读者很难判断实现难度。

4. **例子各自承担不同任务。** 给每个例子标注它证明什么；如果三个例子都只证明“效果惊艳”，就该删减，或补上失败、边界与使用条件。

5. **解释到因果链，而非停在名词上。** 写到“上下文”“记忆”“数据飞轮”“组织协作”时，是否接着说明它怎样改变一次具体任务的结果？

6. **结论没有越过证据。** 一次跑通只支持这次任务的表现，个人感受不能直接代表所有用户，受访者的说法也需要标明来源；检查正文是否把这些区别写清楚。

7. **局限具体到能影响选择。** “仍有提升空间”帮助有限；应写明哪类输入容易失败、需要多少人工检查、哪些成本没有统计，以及这些限制会影响谁。

8. **读完能改变一个行动。** 普通读者能否据此选工具、完成任务、修改流程或调整预期？不必每篇都给教程，但必须把判断连接到读者的实际生活。
